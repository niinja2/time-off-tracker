# Leća 2: Isti skup vrijednosti

Mapa (llm-shiva/lece-integrator/mapa.md) je korištena samo za orijentaciju. Svaki nalaz je provjeren otvaranjem fajla i retka.

## L2-1: Skup Status (PENDING, APPROVED, REJECTED, CANCELLED) napisan na četiri mjesta

Isti skup statusa stoji u Java enumu, u SQL CHECK ograničenju, u TS tipu i u prikaznoj tablici. Dodavanje statusa traži ručnu izmjenu sva četiri mjesta, a SQL i TS nisu povezani s enumom pa kompajler ne javlja propust.

- Dokaz: `backend/src/main/java/com/example/timeoff/domain/Status.java:8` citat: `    PENDING,`
- Dokaz: `backend/src/main/resources/db/migration/V1__schema.sql:29` citat: `status           VARCHAR(20)  NOT NULL CHECK (status IN ('PENDING', 'APPROVED', 'REJECTED', 'CANCELLED')),`
- Dokaz: `frontend/src/lib/types.ts:5` citat: `export type RequestStatus = "PENDING" | "APPROVED" | "REJECTED" | "CANCELLED";`
- Dokaz: `frontend/src/lib/labels.ts:11` citat: `export const STATUS_LABELS: Record<RequestStatus, string> = {`
- Težina: VAŽNO (SQL CHECK je jedino mjesto koje nije provjereno kompajlerom).
- Kirurški refaktor: dodati backend test koji iz V1__schema.sql izvuče listu u CHECK(status IN ...) i usporedi je s `Status.values()`.

Vrste odsustva se navode u Java enumu, SQL CHECK-u, TS tipu i u Record tipu za oznake. Isti problem kao L2-1.

- Dokaz: `frontend/src/lib/labels.ts:5` citat: `export const TYPE_LABELS: Record<TimeOffType, string> = {`
- Težina: VAŽNO.
- Kirurški refaktor: isti test kao u L2-1, proširen na TimeOffType i CHECK(type IN ...).

## L2-3: TYPE_OPTIONS je ručno napisana lista koja duplicira ključeve TYPE_LABELS

Lista vrsta za izbornik je napisana ručno, iako Record<TimeOffType, string> već jamči da su sve vrste u TYPE_LABELS. Dodavanje vrste može ostaviti izbornik bez nove opcije.

- Dokaz: `frontend/src/lib/labels.ts:18` citat: `export const TYPE_OPTIONS: TimeOffType[] = ["VACATION", "SICK_LEAVE", "DAY_OFF"];`
- Težina: SITNO.
- Kirurški refaktor: zamijeniti s `export const TYPE_OPTIONS = Object.keys(TYPE_LABELS) as TimeOffType[];` (redoslijed ključeva u objektu ostaje isti).

## L2-4: Skup aktivnih statusa {PENDING, APPROVED} napisan dvaput u backendu

Pravilo "zahtjev je aktivan" (koristi se za kalendar i za provjeru preklapanja) napisano je u dva servisa, s istim uvjetom. Ako se jedno promijeni a drugo ne, kalendar i pravilo preklapanja se razilaze.

- Dokaz: `backend/src/main/java/com/example/timeoff/service/CalendarService.java:78` citat: `        return status == Status.PENDING || status == Status.APPROVED;`
- Dokaz: `backend/src/main/java/com/example/timeoff/service/RequestService.java:102` citat: `.filter(request -> request.getStatus() == Status.PENDING || request.getStatus() == Status.APPROVED)`
- Težina: VAŽNO.
- Kirurški refaktor: dodati metodu `public boolean isActive()` u Status.java (pored `canTransitionTo`) i koristiti je na oba mjesta.

- Kirurški refaktor: dodati boolean polje `cancellable` u RequestView (backend/.../api/RequestView.java) i u isCancellable vratiti `request.cancellable`.

- Kirurški refaktor: dodati u VisibilityPolicy metodu `boolean showsApprovedOnly(User viewer, User owner)` ili `boolean isFull(...)` pa je pozvati iz CalendarService i VisibilityService.
