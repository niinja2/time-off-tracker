Pregledan kod: backend/src/main/java i frontend/src. Mapa (llm-shiva/lece/mapa.md) služila je za orijentaciju; svaki nalaz provjeren je u fajlu.

## Leća 6. Popis prema radnji

Endpointi koji vraćaju popis "što smiješ napraviti": GET /api/approvals (ApprovalService.pending, uvjet canDecide), GET /api/approvals/cancellable (CancelService.cancellable, uvjet canCancel plus filteri). Ostale radnje (approve, reject, cancel) provjeravaju isti uvjet pri izvršenju. Dodatno, frontend na ekranu Moja odsustva sam računa koje gumbe prikazati, bez popisa s backenda.

**L6-1 (VAŽNO)** Frontend računa "smije li se otkazati" sam i ne zna za pravilo "zahtjev je već počeo". Backend to pravilo ima, pa gumb Cancel ostaje vidljiv za odobreni zahtjev koji je već počeo, a klik vraća 409.
- Za: developer (frontend), uz pregled backend pravila.
- Dokaz: frontend/src/components/MyTimeOffScreen.tsx:36-38, redak 37: `return request.status === "PENDING" || request.status === "APPROVED";`
- Dokaz: backend/src/main/java/com/example/timeoff/service/CancelService.java:92, redak 92: `boolean started = request.getStatus() == Status.APPROVED && hasStarted(request);`
- Kirurški refaktor: u RequestView dodati boolean `cancellable` koji backend popuni pozivom istog pravila (npr. CancelService), a MyTimeOffScreen.tsx:36-38 (isCancellable) zamijeniti čitanjem tog polja.

**L6-2 (VAŽNO, treba provjeriti sa specifikacijom)** Admin smije odobriti i odbiti vlastiti zahtjev. Pravilo za admina je prvo, pravilo "vlastiti zahtjev se ne odobrava" (R3) je iza njega, pa prvo pravilo pobjeđuje. Vlastiti zahtjev admina zato se pojavljuje na popisu za odobravanje (GET /api/approvals) i može se odobriti.
- Za: tim koji vodi specifikaciju (provjeriti je li admin izuzetak namjeran).
- Dokaz: backend/src/main/java/com/example/timeoff/service/ApprovalPolicy.java:18, redak 18: `new Rule((actor, request) -> actor.isAdmin(), true),                   // R2, Q1.1, D15`
- Dokaz: ApprovalPolicy.java:19, redak 19: `new Rule((actor, request) -> request.isSubmittedBy(actor), false),     // R3`
- Kirurški refaktor ako nije namjerno: zamijeniti redoslijed redaka 18 i 19, ili dodati u pravilo admina uvjet `&& !request.isSubmittedBy(actor)`.

**L6-3 (SITNO)** Uvjet "vlastiti zahtjev" napisan je na tri mjesta: u CancelPolicy (pravilo prvo), u ApprovalPolicy (pravilo iza admina) i u CancelService.cancellable kao filter. Sada daju isti rezultat za običnog korisnika, ali se mogu razići ako se jedno promijeni.
- Za: developer (održavanje).
- Dokaz: backend/src/main/java/com/example/timeoff/service/CancelPolicy.java:22, redak 22: `new Rule((actor, request) -> request.isSubmittedBy(actor), false),  // R6, R7`
- Dokaz: backend/src/main/java/com/example/timeoff/service/CancelService.java:67, redak 67: `.filter(request -> !request.isSubmittedBy(actor))`
- Kirurški refaktor: staviti uvjet u jednu metodu (npr. `TimeOffRequest.isOwnedBy(actor)`) i koristiti je na sva tri mjesta.

**L6-4 (SITNO)** Odjeljak "Approved requests" na ekranu za odobravanja prikazuje samo podskup odobrenih zahtjeva, onaj koji backend smatra otkazivim (bez vlastitih i bez počelih). Naslov obećava više nego što se prikaže.
- Za: frontend (naslov) i tester (očekivanja).
- Dokaz: frontend/src/components/ApprovalsScreen.tsx:209, redak 209: `<h2 className="text-lg font-semibold">Approved requests</h2>`
- Dokaz: backend/src/main/java/com/example/timeoff/service/CancelService.java:65-69 (filteri nad APPROVED zahtjevima).
- Kirurški refaktor: preimenovati naslov u "Cancellable approved requests" ili "Approved requests you can cancel".

## Leća 8. Prazno, null i obrezivanje

Mjesta gdje se tekst pretvara u null ili provjerava je li prazan:
- service/Texts.java:9-14 `blankToNull`: prazan i samo-razmakni tekst postaje null, tekst se ne obrezuje.
- ApprovalService.java:44 (komentar odobrenja): `String decisionComment = Texts.blankToNull(comment);`
- CancelService.java:47 (razlog otkazivanja): `String cancelReason = Texts.blankToNull(reason);`
- RequestService.java:54 (razlog zahtjeva): `String reason = Texts.blankToNull(command.reason());`
- ApprovalController.java:68 (komentar odbijanja): `record RejectBody(@NotBlank @Size(max = 500) String comment)` i ApprovalController.java:43-45 (prazno tijelo daje "comment must not be blank").
- AuthController.java:39 (prijava): `record LoginRequest(@NotBlank String username, @NotBlank String password)`.
- Frontend: ApprovalsScreen.tsx:124, 131, 187 i MyTimeOffScreen.tsx:114 šalju prazni tekst kao "" (bez provjere).

Odgovor na pitanje: komentar odobrenja, komentar odbijanja i razlog otkazivanja ne rade isto. Odobrenje i otkazivanje pretvore prazan tekst u null, a odbijanje ga odbije s greškom 400 (provjera je u kontroleru, ne u servisu).

**L8-1 (SITNO)** Komentar odbijanja se ne pretvara u null niti se provjerava u servisu. Servis se oslanja na to da kontroler već odbije prazan tekst. Ako drugi ulaz pozove servis izravno, prazan komentar bi se spremio.
- Za: developer.
- Dokaz: backend/src/main/java/com/example/timeoff/service/ApprovalService.java:52, redak 52: `// The comment is required (R5); the API has already rejected a blank one.`
- Dokaz: ApprovalService.java:59, redak 59: `request.reject(actor, comment, now);` (bez blankToNull, za razliku od redaka 44 i 47)
- Kirurški refaktor: u reject dodati `String decisionComment = Texts.blankToNull(comment);` i provjeru `if (decisionComment == null) throw new InvalidRequestException("comment must not be blank");`.

**L8-2 (VAŽNO)** Stupac "Comment" na ekranu Moja odsustva prikazuje komentar odobrenja, pa razlog otkazivanja nije vidljiv kad je zahtjev prvo odobren s komentarom pa otkazan. Operator `??` uzima prvi neprazan, a ne onaj koji odgovara statusu.
- Za: frontend (korisnik ne vidi razlog otkazivanja).
- Dokaz: frontend/src/components/MyTimeOffScreen.tsx:33, redak 33: `return request.decisionComment ?? request.cancelReason ?? "";`
- Dokaz: backend/src/main/java/com/example/timeoff/domain/TimeOffRequest.java:117-119 (approve upisuje decisionComment, a cancel upisuje cancelReason zasebno, pa oba mogu biti postavljena).
- Kirurški refaktor: za status CANCELLED vratiti cancelReason, inače decisionComment, npr. `request.status === "CANCELLED" ? request.cancelReason ?? "" : request.decisionComment ?? ""`. Ili prikazati oba.

**L8-3 (SITNO)** Nigdje se tekst ne obrezuje (trim). Komentar "  ok  " se sprema s razmacima, a samo-razmakni tekst postaje null. Nema greške, ali je prikaz nedosljedan.
- Za: developer (odluka je li potrebno obrezivanje).
- Dokaz: backend/src/main/java/com/example/timeoff/service/Texts.java:10-14, redak 14: `return text;` (vraća tekst kakav je došao)
- Kirurški refaktor: u blankToNull vratiti `text.strip()` nakon provjere, ako se želi jedinstveno spremanje.
