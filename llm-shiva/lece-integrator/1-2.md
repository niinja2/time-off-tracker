# Leće 1 i 2: ponavljanja u backendu i frontendu

Pregledano: backend/src/main (service, domain, security, api dijelovi koji su relevantni, V1__schema.sql) i frontend/src (lib/labels.ts, lib/types.ts, components/MyTimeOffScreen.tsx, ApprovalsScreen.tsx, CalendarScreen.tsx). Nisu otvoreni: User.java, BalanceController, ApiExceptionHandler, api.ts, month.ts, ostali api kontroleri. Svaki nalaz je provjeren otvaranjem fajla.

Legenda: VAŽNO = ponavljanje pravila poslovne logike na više mjesta, pa se može razići. SITNO = ponavljanje koda ili popisa bez utjecaja na pravila.

## Leća 1: Isto tijelo, drugo ime

Jednostavno: ista logika (ili gotovo ista) napisana je na više mjesta. Ispod su nalazi redom.

**L1-1. Metoda `leadsTeamOfOwner` ima isto tijelo u dvije policy klase.**
Što: ApprovalPolicy i VisibilityPolicy imaju metodu s istim imenom i istim tijelom: "ima li korisnik vodeći položaj u nekom timu vlasnika". Ovo je pravilo tko je voditelj, a ono mora biti isto za odobravanje i za vidljivost.
Dokaz:
- backend/src/main/java/com/example/timeoff/service/ApprovalPolicy.java:37 — `.anyMatch(actor::leads);`
- backend/src/main/java/com/example/timeoff/service/VisibilityPolicy.java:40 — `.anyMatch(viewer::leads);`
Težina: VAŽNO. Ako se pravilo promijeni u jednoj klasi, druga ostaje stara.
Kirurški refaktor: dodati u User metodu `leadsTeamOf(User owner)` (`owner.getTeams().stream().anyMatch(this::leads)`) i obje policy klase pozivaju nju.

**L1-2. `sharesTeam` i `leadsTeamOfOwner` u VisibilityPolicy imaju isti oblik tijela.**
Što: obje metode prolaze kroz `owner.getTeams()` i traže jedan tim s predikatom koji ovisi o viewer. Razlika je samo predikat.
Dokaz:
- backend/src/main/java/com/example/timeoff/service/VisibilityPolicy.java:39-40 — `return owner.getTeams()` / `.anyMatch(viewer::leads);`
- backend/src/main/java/com/example/timeoff/service/VisibilityPolicy.java:44-46 — `return owner.getTeams()` / `.anyMatch(viewer::isMemberOf);`
Težina: SITNO.
Kirurški refaktor: jedna privatna metoda `anyTeamOf(owner, Predicate<Team>)` koju obje metode koriste. Alternativa je ostaviti, jer su dvije linije.

**L1-3. Mehanizam "prvo pravilo koje vrijedi odlučuje" ponavlja se tri puta.**
Što: tri policy metode imaju isto tijelo: stream po listi pravila, filter po `applies`, `findFirst`. Razlikuju se samo u tome što se vraća.
Dokaz:
- backend/src/main/java/com/example/timeoff/service/ApprovalPolicy.java:26-28 — `return RULES.stream()` / `.filter(rule -> rule.applies().test(actor, request))` / `.findFirst()`
- backend/src/main/java/com/example/timeoff/service/VisibilityPolicy.java:26-28 — `return RULES.stream()` / `.filter(rule -> rule.applies().test(viewer, owner))` / `.findFirst()`
- backend/src/main/java/com/example/timeoff/service/CancelPolicy.java:39-41 — `return rules.stream()` / `.filter(rule -> rule.applies().test(actor, request))` / `.findFirst();`
Težina: SITNO (tri linije, ali ista ideja na tri mjesta).
Kirurški refaktor: generička statička metoda `firstMatch(List<Rule>, ...)` ili zajednički helper; svaka policy zove nju.

**L1-4. Komparator `BY_START_THEN_ID` je definiran dvaput, identično.**
Dokaz:
- backend/src/main/java/com/example/timeoff/service/ApprovalService.java:19-21 — `Comparator` `.comparing(TimeOffRequest::getStartDate)` `.thenComparing(TimeOffRequest::getId);`
- backend/src/main/java/com/example/timeoff/service/CancelService.java:20-22 — ista tri linije
Težina: SITNO.
Kirurški refaktor: premjestiti konstantu u TimeOffRequest (`public static final Comparator<TimeOffRequest> BY_START_THEN_ID`) i koristiti je u oba servisa.

**L1-5. Metode `pending` i `cancellable` imaju isti oblik tijela.**
Što: obje učitaju aktora, uzmu zahtjeve po statusu, filtriraju po policy, sortiraju po `BY_START_THEN_ID`. Razlikuju se status i dodatni filter (CancelService još filtrira `!hasStarted`).
Dokaz:
- backend/src/main/java/com/example/timeoff/service/ApprovalService.java:69-73 — `return requestRepository.findByStatus(Status.PENDING)` / `.stream()` / `.filter(request -> approvalPolicy.canDecide(actor, request))` / `.sorted(BY_START_THEN_ID)` / `.toList();`
- backend/src/main/java/com/example/timeoff/service/CancelService.java:65-71 — `return requestRepository.findByStatus(Status.APPROVED)` / `.stream()` / `.filter(request -> !request.isSubmittedBy(actor))` / `.filter(request -> cancelPolicy.canCancel(actor, request))` / `.filter(request -> !hasStarted(request))` / `.sorted(BY_START_THEN_ID)` / `.toList();`
Težina: SITNO.
Kirurški refaktor: ostaviti kao jesu; ako se doda treći popis, izvući zajedničku metodu `listDecidable(status, predicate)`.

**L1-6. `loadViewer` je identičan u dva servisa.**
Dokaz:
- backend/src/main/java/com/example/timeoff/service/VisibilityService.java:99-101 — `return userRepository.findById(viewerId)` / `.orElseThrow();`
- backend/src/main/java/com/example/timeoff/service/CalendarService.java:131-133 — ista dva retka
Dodatno: isti uzorak (`findById(...).orElseThrow()`) stoji i u ApprovalService.java:76-78 (`loadActor`), CancelService.java:43-44 i 62-63 (inline), BalanceService.java:53-54.
Težina: SITNO.
Kirurški refaktor: jedna metoda za učitavanje korisnika (npr. u UserRepository kao default metoda `require(id)`) i pozivi na nju.

**L1-7. Dohvat zahtjeva s iznimkom "Request not found" je kopiran tri puta.**
Dokaz:
- backend/src/main/java/com/example/timeoff/service/ApprovalService.java:83-84 — `.orElseThrow(() -> new NotFoundException("Request not found"));`
- backend/src/main/java/com/example/timeoff/service/CancelService.java:45-46 — ista linija
- backend/src/main/java/com/example/timeoff/service/VisibilityService.java:69-70 — ista linija
Težina: SITNO (ako se promijeni tekst poruke, treba na tri mjesta).
Kirurški refaktor: default metoda `findOrThrow(Long id)` u TimeOffRequestRepository.

**L1-8. Metode `approve` i `reject` u ApprovalService imaju gotovo isto tijelo.**
Dokaz:
- backend/src/main/java/com/example/timeoff/service/ApprovalService.java:42-49 — `User actor = loadActor(actorId);` / `TimeOffRequest request = loadDecidable(requestId, actor);` / `Instant now = clock.instant();` / `request.approve(actor, decisionComment, now);`
- backend/src/main/java/com/example/timeoff/service/ApprovalService.java:55-61 — ista tri linije početka i `request.reject(actor, comment, now);`
Razlika: approve prije toga zove `Texts.blankToNull(comment)`, reject ne.
Težina: SITNO.
Kirurški refaktor: ostaviti; razlika u komentaru je namjerna (R5 traži komentar kod odbijanja). Nije potrebna promjena.

## Leća 2: Isti skup vrijednosti

Jednostavno: isti popis vrijednosti (PENDING, APPROVED, ...) ili ista grupa vrijednosti stoji na više mjesta u kodu, u bazi i u frontendu. Ako se doda ili promijeni vrijednost, mora se mijenjati na svakom mjestu.

**L2-1. Skup statusa je zapisan u Javi, SQL-u i frontendu.**
Dokaz:
- backend/src/main/java/com/example/timeoff/domain/Status.java:8-11 — `PENDING,` / `APPROVED,` / `REJECTED,` / `CANCELLED;`
- backend/src/main/resources/db/migration/V1__schema.sql:29 — `status VARCHAR(20) NOT NULL CHECK (status IN ('PENDING', 'APPROVED', 'REJECTED', 'CANCELLED')),`
- frontend/src/lib/types.ts:5 — `export type RequestStatus = "PENDING" | "APPROVED" | "REJECTED" | "CANCELLED";`
- frontend/src/lib/labels.ts:11-16 — `STATUS_LABELS: Record<RequestStatus, string>` s ključevima PENDING, APPROVED, REJECTED, CANCELLED
Težina: VAŽNO. Dodavanje statusa mijenja četiri mjesta, a SQL CHECK i Java enum se ne provjeravaju međusobno pri prevođenju.
Kirurški refaktor: za frontend je TypeScript već prijavio bi nepotpun Record. Za bazu: nova Flyway migracija koja mijenja CHECK pri svakoj promjeni enuma. Nema druge sigurne jednostavne promjene.

**L2-2. Skup vrsta odsustva je zapisan u Javi, SQL-u i frontendu, a u labels.ts dvaput.**
Dokaz:
- backend/src/main/java/com/example/timeoff/domain/TimeOffType.java:4-6 — `VACATION,` / `SICK_LEAVE,` / `DAY_OFF`
- backend/src/main/resources/db/migration/V1__schema.sql:25 — `CHECK (type IN ('VACATION', 'SICK_LEAVE', 'DAY_OFF'))`
- frontend/src/lib/types.ts:3 — `export type TimeOffType = "VACATION" | "SICK_LEAVE" | "DAY_OFF";`
- frontend/src/lib/labels.ts:5-9 — `TYPE_LABELS` s ključevima VACATION, SICK_LEAVE, DAY_OFF
- frontend/src/lib/labels.ts:18 — `export const TYPE_OPTIONS: TimeOffType[] = ["VACATION", "SICK_LEAVE", "DAY_OFF"];`
Težina: VAŽNO. TYPE_OPTIONS je ručno napisana lista koja može odstupiti od TYPE_LABELS, a ta dva popisa bi trebala biti isti.
Kirurški refaktor: u labels.ts zamijeniti ručni popis: `export const TYPE_OPTIONS = Object.keys(TYPE_LABELS) as TimeOffType[];`. Redoslijed ostaje jer Object.keys čuva redoslijed unosa.

**L2-3. Skup "PENDING ili APPROVED" ponavlja se u backendu i frontendu s različitim imenima.**
Što: ista dva statusa koriste se za tri različita pravila: prikaz u kalendaru, provjera preklapanja, i može li korisnik otkazati. Pravila nisu ista, ali je skup vrijednosti isti, pa bi se mogao promijeniti na jednom mjestu.
Dokaz:
- backend/src/main/java/com/example/timeoff/service/CalendarService.java:76-78 — `Status status = request.getStatus();` / `return status == Status.PENDING || status == Status.APPROVED;`
- backend/src/main/java/com/example/timeoff/service/RequestService.java:102 — `.filter(request -> request.getStatus() == Status.PENDING || request.getStatus() == Status.APPROVED)`
- frontend/src/components/MyTimeOffScreen.tsx:36-38 — `function isCancellable(request: TimeOffRequest): boolean {` / `return request.status === "PENDING" || request.status === "APPROVED";`
Težina: VAŽNO. Frontend isCancellable kopira backendovo pravilo za otkazivanje (CancelPolicy). Ako se pravilo promijeni na backendu, gumb na ekranu ostaje pogrešan.
Kirurški refaktor: u Status.java dodati `public boolean isOpen() { return this == PENDING || this == APPROVED; }` i koristiti ga u CalendarService i RequestService. Na frontendu: isCancellable može ostati, ali bi ga trebalo označiti kao kopiju backend pravila.

**L2-4. Usporedbe vrijednosti Access enuma su na više mjesta.**
Što: pitanje "je li vidljivost FULL" i "je li LIMITED" ponavlja se u dva servisa. Komentar u CalendarService također ponavlja značenje FULL i LIMITED.
Dokaz:
- backend/src/main/java/com/example/timeoff/service/CalendarService.java:87 — `if (access == Access.FULL) {`
- backend/src/main/java/com/example/timeoff/service/CalendarService.java:90 — `if (access == Access.LIMITED && approved) {`
- backend/src/main/java/com/example/timeoff/service/VisibilityService.java:96 — `return visibilityPolicy.access(viewer, owner) == Access.FULL;`
- backend/src/main/java/com/example/timeoff/service/CalendarService.java:81 — komentar `// FULL: pending and approved, with type and status (Q42, Q43). LIMITED: approved only, name and dates (Q47).`
Težina: SITNO.
Kirurški refaktor: metode `isFull()` na Access enumu. Alternativa je ostaviti, jer je enum mali.

**L2-5. Usporedbe s APPROVED i PENDING su raspršene po domeni i servisima.**
Dokaz (izbor):
- backend/src/main/java/com/example/timeoff/service/CancelService.java:65 — `findByStatus(Status.APPROVED)`
- backend/src/main/java/com/example/timeoff/service/CancelService.java:92 — `request.getStatus() == Status.APPROVED && hasStarted(request)`
- backend/src/main/java/com/example/timeoff/service/BalanceService.java:57-58 — `vacationDays(requests, year, Status.APPROVED);` i `Status.PENDING);`
- backend/src/main/java/com/example/timeoff/domain/TimeOffRequest.java:82 — `return status == Status.PENDING;`
Težina: SITNO. Enum je tipiziran, pa nema greške, ali nema ni jedne metode koja to izražava.
Kirurški refaktor: ostaviti; eventualno uvesti `isApproved()`/`isPending()` na Status ako se broj mjesta poveća.

**L2-6. VACATION se koristi kao posebno pravilo na dva mjesta u Javi, a kao zadana vrijednost na frontendu.**
Dokaz:
- backend/src/main/java/com/example/timeoff/service/BalanceService.java:73 — `.filter(request -> request.getType() == TimeOffType.VACATION)`
- backend/src/main/java/com/example/timeoff/service/RequestService.java:112 — `if (command.type() != TimeOffType.VACATION) {`
- frontend/src/components/MyTimeOffScreen.tsx:18 — `const EMPTY_FORM: NewRequest = { type: "VACATION", startDate: "", endDate: "", reason: "" };`
Težina: SITNO. Pravilo "samo godišnji ima saldo" je u dvije Java klase, a frontend zna zadanu vrstu.
Kirurški refaktor: ostaviti; eventualno `TimeOffType.countsAgainstBalance()` u enumu ako se pravilo proširi.

**L2-7. Frontend ponavlja značenje statusa CANCELLED i PENDING u funkciji za tekst.**
Dokaz:
- frontend/src/components/MyTimeOffScreen.tsx:23 — `const byName = request.status === "CANCELLED" ? request.cancelledByName : request.decidedByName;`
- frontend/src/components/MyTimeOffScreen.tsx:25 — `if (request.status === "PENDING" || !byName) {`
Težina: SITNO. Pravilo "tko je odlučio" ovisi o statusu i zapisano je kao literali.
Kirurški refaktor: ostaviti; alternativa je u types.ts imati mapu status na polje s imenom, ali to nije nužno.
